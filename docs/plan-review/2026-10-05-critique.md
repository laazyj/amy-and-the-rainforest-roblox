# Independent critique of the development plan (revision 1) and responses

An independent review agent was asked to critique revision 1 of
`docs/DEVELOPMENT_PLAN.md` adversarially, verifying tool claims by web
search. Its findings are listed below with the change made in revision 2.
Severity is the reviewer's.

| # | Severity | Finding | Response in revision 2 |
|---|---|---|---|
| 1 | Blocker | Jest-Lua only runs inside Roblox, not under Lune, so "one test library for tiers 1 and 2" was a false premise. | Tier 1 uses a small Lune-native runner; tier 2 uses Jest-Lua or TestEZ in-engine; fixtures, fake player and event scripts are shared, runners are not. |
| 2 | Blocker | One API key scoped to both experiences and available to PR jobs and to the agent could publish to the public Release experience. | Two keys. Dev key as a repo secret; Release key only in the gated `release` environment. Agent never holds a key; uploads run as a CI job. `pull_request` only, no fork secrets. Publish and test scripts refuse Release IDs outside the release job. |
| 3 | Blocker | Public-release prerequisites for a 7 to 12 audience were missing: Experience Guidelines questionnaire (account must be 30 days old; without it the game is treated as 13+), no off-platform links, no full name of a minor. | A Roblox compliance list is now part of Phase 1 and the release checklist. Tier 0 fails on `http` in content and UI strings. Credits say "Clara" only. Max Players = 1, Allow copying off, automatic translation off. |
| 4 | Major | World state is shared across players; the plan never set server size. | Max Players = 1 is an invariant asserted by tier 2, with a two-fake-player isolation test. Co-op is documented as a redesign. |
| 5 | Major | Tiers 0 to 2 cannot test the client, and Release could ship without tier 3. | Client logic extracted into a pure view-model tested in tier 1; remote payloads validated against a core contract in tier 2; tier 3 mandatory for Release; real phone on the checklist. |
| 6 | Major | The fake player teleports, so an unreachable zone would still pass. | Tier 2 pathfinding reachability test from spawn to every zone and prompt; Phase 0 spike on whether physics steps in Luau Execution decides whether real traversal is possible in tier 2. |
| 7 | Major | Luau Execution writes to real Dev DataStores. | Store-name prefix from config, `test-<runId>` stores with cleanup, runner refuses Release IDs, session-lock release test. |
| 8 | Major | `run-in-roblox` is unmaintained and edit-mode only; the official Studio MCP server replaced the archived Rust server. | Studio built-in MCP server is the bridge, wrapped behind one module; Studio version pinned and reported; launchd agent in a GUI session. |
| 9 | Major | Rigged, custom-animated characters in Phase 1 are not deliverable by a Linux agent. | Phase 1 uses `HumanoidDescription` avatars with built-in animations and free animated rigs; custom rigs move to Phase 2 as a human-in-Studio task. Player-is-Amy decided. |
| 10 | Major | The agent cannot see or hear the game; "proven feature set without guidance" overstated perceptual work. | Briefs declare logic-provable versus perceptual scope; perceptual work requires the Mac and human review; agent reads contact sheets; per-scene baselines with tolerance diffs. Stated as a real constraint in the introduction. |
| 11 | Major | No defined path to fetch free Creator Store assets from Linux. | Phase 0 spike with two candidates (Luau Execution `InsertService` + `SerializationService`, or Mac MCP insert); manifest records id, creator, licence, moderation status; tier 0 fails on unknown asset ids. |
| 12 | Major | PR Saved versions test the branch head, not the merge result; release rebuilds; dashboard rollback unaudited; save migrations forward-only; tester access undocumented; Studio publish overwrites CI. | Branches must be up to date with `main`; release downloads the tagged artifact by SHA with checksum; rollback is re-running release with a previous tag, limited to one schema version, with a tolerance test; friends requirement documented; "only CI publishes" rule. |
| 13 | Major | Phase 0 refactor had no baseline test before the refactor; Mac in Phase 0 depends on owner time. | Characterization golden test against the current `StoryServer` is step 1 of Phase 0; Mac moves to Phase 1; Phase 0 re-estimated at 3 weeks, Phase 1 at 5 to 6. |
| 14 | Major | "Chapters are data only" is untrue; each chapter needs scripted moments. | Chapter = data + hooks, with a `World` interface; tier 0 checks hooks exist. |
| 15 | Minor | Content uses Roblox datatypes that are not globals under Lune. | Content stores positions and colours as plain tables, converted in adapters. |
| 16 | Minor | Narration is the biggest quality lever for non-fluent readers and makes ID verification a prerequisite. | Narration added to Phase 1 and section 7; ID verification is a prerequisite; lines batched per chapter. |
| 17 | Minor | Camera, onboarding, readability and automatic translation unspecified. | `docs/design/feel.md` added to Phase 0; camera shots, onboarding, text rules and translation off are in the plan. |
| 18 | Minor | Dependency list heavier than the game. | Dependencies cut to toolchain, ProfileStore and one in-engine runner; UI framework deferred; small owned wrappers instead of promise, signal and net libraries. |
| 19 | Minor | "60 fps on a mid-range phone" cannot be measured by any tier. | Budgets replaced by measurable proxies per tier; phone target moved to the release checklist on a real device. |
